# Диагностическая карта финансового пути — Монтериум

Одностраничный сайт-анкета ([index.html](index.html)), которую эксперт заполняет вместе с клиентом на созвоне.

## Структура анкеты (6 блоков)

1. **Знакомство** — имя, дата, точка А/Б
2. **Финансовая ситуация** — доход/расход, подушка, кредиты
3. **Цели** — калькулятор сложного процента (достижима ли цель при текущей стратегии)
4. **Опыт инвестирования** — чек-листы инструментов
5. **Главный барьер**
6. **Резюме** — выбор рекомендуемого курса-маршрута из 5 вариантов

## Дополнительно

- Живой пересчёт калькулятора и итогового маршрута по ходу заполнения
- Экспорт в PDF (`window.print()`)
- Демо-модалка «отправка в Битрикс24» (пока имитация, не реальная интеграция)
- **Сохранение анкет** — кнопка «💾 Сохранить анкету» отправляет данные в Google Таблицу через Google Apps Script ([apps-script/Code.gs](apps-script/Code.gs), инструкция в [apps-script/README.md](apps-script/README.md)); URL веб-приложения уже вписан в код.

## Технически

Чистый HTML/CSS/JS, без сборки и серверного PDF-сервиса. Исходные шрифты
Golos Text и Cormorant Garamond хранятся в `assets/fonts/` вместе с лицензиями.
В production не нужны Node.js или npm-пакеты.

## Расчёт стратегии

`assets/strategy.js` повторяет формулы вкладки «Сложный процент » из
[исходной таблицы](https://docs.google.com/spreadsheets/d/1J6IQbyB4afKsKSn3wM-wPJSed4tXZWYNNFTuTB3QMoE/edit?gid=2091821895)
(проверено 14.09.2026). Ставка взята из D7: 30% годовых. D11 содержит
стартовый капитал без первого пополнения. Со второго месяца прибавляется
ежемесячный взнос; каждый 12-й месяц сначала начисляется 30% на предыдущий
остаток, затем добавляется взнос. Это именно порядок исходной таблицы.
Доля цели: `INDEX(D:D,10+D3*12)/D6` (F5). Срок — целое число от 1 до 20 лет,
как в годовых строках исходного расчёта. Пустые и некорректные параметры
дают прочерки; нулевой старт или взнос нужно указать явно.

Пример: цель 6 000 000 ₽, 5 лет, старт 1 000 000 ₽, взнос 5 000 ₽/месяц →
**4 386 162,50 ₽, 73,10%**. Нужный ежемесячный взнос вычисляется обратным
расчётом по той же модели. Вместо ручного ввода доходности в анкете показаны
две автоматические строки. Их значения, карточка стратегии и PDF совпадают.

Расчёт выполняется локально: клиентские данные не записываются в общие
расчётные ячейки таблицы. Это зафиксированная копия формул, не живая
синхронизация: при изменении исходной модели нужно обновить `strategy.js`
и контрольные примеры в `tests/strategy.test.cjs`. Существующий Apps Script
по-прежнему сохраняет ответы, ставку 30% и готовые результаты в лист «Анкеты».

## Экспорт PDF

Нажмите **«Скачать PDF»**, в системном окне печати выберите **«Сохранить как PDF»**
и сохраните файл. По умолчанию задан A4, книжная ориентация, поля 12 мм.
Используйте масштаб 100% и все страницы. Имя файла формируется из имени
клиента и даты диагностики. В Chrome/Edge с поддержкой CSS margin boxes
добавляются номера страниц. Обычный Ctrl+P тоже подготавливает значения полей.

Экспорт использует движок печати браузера вместо html2pdf/html2canvas:

- `assets/pdf-export.js` создаёт из текущей страницы изолированную печатную
  копию, подставляет полные ответы, актуальные переключатели и выбранные
  инструменты; обработчики событий и служебные элементы в копию не попадают.
- `assets/print.css` сохраняет исходный дизайн, сетки, цвета и SVG-калькулятор,
  задаёт A4 и правила переноса. Короткие карточки остаются целыми; ответ выше
  одного листа продолжается на следующих страницах без ограничения длины.
- Перед печатью загружаются все начертания локальных шрифтов. В PDF остаются
  выделяемый текст, чёткая векторная графика и действующие ссылки курсов.
- Экспорт не отправляет ответы на сервер и не меняет заполненную форму.
  Ошибка подготовки отображается на странице; можно повторить попытку.
  Отмена системного диалога не считается успешным сохранением.

**Изменение сценария:** PDF сохраняется через системный диалог, а не прямым
скачиванием картинки. Это позволяет сохранить настоящую HTML/CSS-вёрстку
и векторный текст без отдельного сервера. Настройки печати пользователь может
переопределить в браузере. Основная проверка выполнена в Chromium (Chrome/Edge);
окно печати и колонтитулы в других браузерах могут отличаться.

Для публикации обновления загрузите **`index.html` и весь каталог `assets/`**
на тот же статический хостинг с сохранением путей. CSS должен отдаваться
как `text/css`, JS — `text/javascript`. Каталоги тестов, `node_modules`, `tmp`
и файлы npm для работы сайта не нужны. Google Apps Script не менялся.

## Локальная проверка

Для тестов нужен Node.js 22.13+ (dev-зависимости не используются на сайте).

```sh
npm ci
npx playwright install chromium
npm test
```

Тесты проверяют обычную и пустую анкету, все ответы и варианты маршрутов,
длинные строки, отсутствие обрезания и пустых листов, нули, очистку старых
значений, мобильную ширину, отмену и повтор экспорта, ошибку загрузки ресурсов.
Для проверки системного диалога его вызов подменяется; само создание PDF
выполняется настоящим Chromium из подготовленного HTML. Все страницы
демо-анкеты и стрессовый пример рендерятся в PNG для визуальной проверки.
Файлы проверки сохраняются в `tmp/pdfs/` и не включаются в Git.

```sh
npm run serve
```

Откройте http://127.0.0.1:4173. Для демонстрационных данных можно выполнить
`fillDemo()` в консоли разработчика. Для визуального осмотра другого PDF:

```sh
node tools/pdf-inspect.cjs path/to/file.pdf tmp/pdfs/preview
```
